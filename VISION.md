# SHUTTER — The Vision

**Founder-approved product direction · September 11, 2026**  
**Product domain:** `shutter.video`

> SHUTTER — an intelligent production environment where captured reality, generated reality, music, editing and finishing become the same medium.

Dom approved the preceding ideation message as the product vision and asked that it be saved in this repository. The complete message is preserved in [the original vision archive](docs/vision/2026-09-11-original-message.md), including its wording, examples, feature directions, links and proposed build order. This entry point is an implementation guide beside that archive, not a replacement for it.

## The experience we are building toward

Bring a finished song from FL Studio, real camera footage, photographs and generated material into one production. Find the right moments inside the sources. Cut to the music. Continue a shot, bridge two worlds or propose a transformation. Compare the resulting candidates in context, without losing the original performance, the song, the intended timing or the option to change your mind. Finish and hand off deliberate editions of the same work.

The aim is not a copy of every professional application, or a generator that leaves the creator managing disconnected downloads. It is one coherent, artist-directed production environment that remembers the work.

## Preserve the complete ambition

The original vision covers Production Memory / Shutter Brain; Generative Inserts; Take Stacks and Jam Cut; Continuity Brain / World Bible; Director proposals; branching edits; optional enhancement; tracked masks; Music Video Auto Draft; Shutter Look; camera ingest and verified backups; the Delivery Matrix; revision-bound review; and Shutter Lab. Intent-based model routing connects these workflows without making provider selection the center of the experience.

## The next pivotal product slice

**Production Memory → Generative Inserts + Take Stacks.**

Start with an end-to-end, reviewable journey rather than building each feature as a separate application:

1. Search imported material and return actual source intervals with evidence. Distinguish measured metadata, user labels, model interpretations and accepted observations; do not invent missing camera metadata or subject identity.
2. Select an interval for a timeline shot while preserving its source identity and the fixed song clock.
3. Prepare a continuation or bridge from reviewed reference frames and the surrounding edit. Confirm that the selected adapter supports the requested inputs and duration; an endpoint frame is a conditioning input, not a guarantee of a seamless result.
4. Present the planned request, data leaving the device, provider, cost estimate and hard spending limit before explicit submission. Reconcile uncertain submissions rather than blindly repeating them.
5. Store outputs as unaccepted alternatives under the relevant shot. Compare them against the original; acceptance changes only the intended selection and remains undoable.
6. Save, reopen, recover and export the same accepted decisions. Qualify actual playback and native-editor handoffs with real fixtures before making release claims.

This is the next product priority, not authorization to skip unfinished integration, media safety, color handling or existing release gates. The original message's complete longer-term sequence remains in the archive. Reuse verified foundations in the current code; do not assume every experimental branch or conversation package is integrated.

## Non-negotiable product behavior

- **The artist directs.** Changes are bounded proposals; protected shots, source files, mastered sound and accepted revisions are not silently replaced.
- **One production, reversible decisions.** Alternatives, derived media, source ranges, references and receipts stay connected without duplicating originals unnecessarily.
- **Evidence before certainty.** Intended, observed and accepted continuity are different records. Search confidence, color assumptions and incomplete verification must remain visible.
- **Explicit processing and spending.** Local analysis is the preferred direction; cloud transfers and paid generation require an understandable, authorized path. Ordinary resizing is not neural reconstruction. No hidden enhancement bill.
- **Preservation must be demonstrated.** Pixel-identical protected regions require a validated compositing path; a model prompt alone cannot establish that guarantee.
- **Useful interoperability.** Describe what is transferred, baked in, separately supplied or unsupported. Never claim universal native-project compatibility from an exported media package alone.
