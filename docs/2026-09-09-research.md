# Shutter research and product decisions

September 9, 2026. This record separates inspected product behavior, source claims, local results and proposed work. It is not a claim that Shutter has reached commercial cinema quality.

## The product decision

Shutter is a standalone production system for Eternities. Its defining work is to carry characters, places, performances and story state through a sequence of shots, revisions and episodes. Keep Moment as a direct image-and-direction path into the same underlying assets and jobs. A filmmaker should be able to start with a single compelling moment and develop it into a production without re-importing or losing the original.

The September 6 Astra Godspec establishes the broader studio ambition: editing, sound, export, reliable storage, model routing and professional product polish. The current milestone concentrates on the first dependency: a production that actually retains its references and executes recoverable local shots. Pixel remains the Lunari Cinema identity; the standalone Shutter work does not rename Pixel or replace Lunari's timeline.

## Higgsfield teardown

### Observed studio controls

The public studio's exposed browser tools were inspected without submitting generations or buying credits. Cinema v4 exposes 4–30-second duration, 480p/720p/1080p output, up to 50 reference images, camera/lens options, genre, light direction and pacing. These are observed controls. They do not by themselves establish physically accurate cameras or cross-episode identity stability. The studio also retains older model generations, so a product must bind each take to its actual model and settings rather than a mutable display label.

The published [Cinema Studio 4.0 description](https://higgsfield.ai/blog/cinema-studio-4-0) emphasizes longer shots, reference capacity and directed motion. The transferable product pattern is a readable filmmaking vocabulary with substantial controls behind it. Shutter should keep camera and performance direction visible while recording precise values in the saved take specification. It should not imply that selecting a lens name guarantees optical equivalence.

### Story, editing and the fast path

Higgsfield's [script-to-storyboard workflow](https://higgsfield.ai/blog/script-to-ai-storyboard-shot-list) connects script, boards and video generation. This is valuable because the user develops one production rather than a disconnected pile of prompts. Shutter extends that pattern with explicit cast/place versions, story state before and after each shot, chosen takes and continuity review. A rejected face or prop state should invalidate that take, not force a new episode-wide generation.

Moment remains deliberately smaller: one reference, one direction, one saved shot. It uses the same storage and render lifecycle as Production. It should later support continuation, branching and promotion into a sequence while retaining the original input and take history.

### The exact Blender/Claude integration

The [official Blender add-on page](https://higgsfield.ai/plugins/blender) confirms the integration the user described. It advertises scene building, meshes, rigged character animation, images, video, cameras and assets inside Blender. Its separate bridge endpoint connects an agent to the add-on; the regular MCP endpoint generates assets. Generations use the account's existing credits, so this is not a free local inference path. The published compatibility range is Blender 4.2–5.1, while this host has 5.2.1. We did not install or execute the Higgsfield add-on, connect an account or verify its generated quality.

Shutter's useful adaptation is a persistent set with explicit actors, props and cameras. We produced an actual original `.blend`, three camera renders and geometry passes locally. A multimodal video model must then consume a rendered motion reference in its motion role, plus separate appearance references. A description of a dolly move and a single input image are weaker controls than a full rendered trajectory.

The [Blender Lab MCP project](https://www.blender.org/lab/mcp-server/) provides an official integration direction, but its current implementation exposes unrestricted generated Python. This build uses a bounded original scene generator in a new Blender process. An agent bridge is still future work; it should call the same production commands and act on identified scene objects instead of secretly creating another source of project state.

## Model selection under a zero-spend constraint

The user's intended comparison class is Seedance 2.0 / Kling 3: several reference modalities working together. The chosen local target should be judged by what it can condition on, not only by resolution or parameter count.

| Candidate | Relevant capability | Decision for this machine and product |
| --- | --- | --- |
| Installed Wan 2.2 TI2V 5B | Text plus a first image, local short videos | Execute a declared pipeline baseline with existing files. It cannot qualify audio, reference-video or independent multi-character conditioning. |
| MiniMax H3 Ref2VA | Image, video and audio context with audio/video output | Preferred multimodal research target. Licensing for the intended deployment and actual Windows/Ampere memory behavior remain unresolved. |
| MiniMax H3 FL2VA | Text with optional first/last frames and audio/video output | Useful shot endpoint control, but it is a different checkpoint and does not replace the Ref2VA test. |

| Installed FLUX.2 Klein 4B | Local image generation | A future fallback for image assets; no fresh local image benchmark in this milestone. |
| Built-in Codex image generation | Original designs and reference-based image edits | Used now for the three master/close-up reference assets. Exact backend variant is not exposed by this tool. |

The [official Wan guide](https://docs.comfy.org/tutorials/video/wan/wan2_2) documents a small local TI2V route. The installed files and earlier proof clips were found on disk. Those older clips establish previous activity, not fresh results under this request. The new run uses a native workflow with its actual start-image input connected; the first-party donor graph did not have that input bound.

### H3: what is open, what fits, what is unresolved

MiniMax's [official repository](https://github.com/MiniMax-AI/MiniMax-H3) distinguishes FL2VA and Ref2VA. The latter supports up to nine images, three video clips and three audio clips, with a combined-file limit. Native output is 24 fps with stereo audio. The complete advertised system also includes hosted Context-IR and 2K regeneration; downloading a base checkpoint does not reproduce the whole hosted stack. Shutter needs its own explicit context compiler and an honest record of which input modalities a local adapter consumes.

The [official license](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/LICENSE), dated August 2, excludes US, EU, UK and South Korea from its territory and invites separate permission for deployment there. No H3 weights have been downloaded or run in this task. This is a deployment-rights issue distinct from whether the model can technically fit. Do not quietly switch to a renamed quantization and treat the license as absent.

The [published low-memory experiment](https://github.com/Tomiigo/minimax-h3-16gb) is strong enough to keep hardware feasibility open: it reports Ref2VA under an 8,188 MiB cap on an RTX 5070 Ti and a 32 GB system-memory limit. That is not a physical 8 GB GPU test, and the author explicitly does not validate Windows or Ampere. The recipe's nvfp4 encoder loses native compute support below Blackwell. Its timing is not a prediction for this RTX 3080. The initial raw-parameter-size dismissal was too strong and has been corrected.

The installed ComfyUI already contains native H3 reference nodes for images, video tracks, paired video audio and standalone audio. Once licensing is resolved, qualify a pinned low-memory Ref2VA workflow on this host with one original character image and one original short motion reference. Record exact quantization, dimensions, frames, audio, wall time, VRAM, RAM and output quality. Increase the reference count only after that succeeds. Compare it with the same shot intent, not an unrelated viral demo.

## Continuity by construction, and its limits

1. **Create the originals.** Character turnarounds, expression and costume references, prop dimensions, environment layouts and a restrained visual language. Use actual selected images as identity anchors; do not regenerate every shot from a repeated description alone.
2. **Define the scene.** Who is present, where each actor is, which props they hold, time of day, lighting, conversation axis and facts known at that point in the story. Intent is distinct from what a rendered take actually depicts.
3. **Direct a bounded shot.** Choose duration, framing, action, speech and sound. Bind each source to a role: appearance, setting, pose, camera motion, voice, first frame or last frame. Preserve the boundary between “borrow this motion” and “copy this person's face.”
4. **Render a candidate.** Save the exact input versions, workflow, model files/quantization, seed and provider receipt. Preserve all output bytes. A transport timeout does not authorize duplicate submission.
5. **Review the cut.** Inspect start, middle and end, and the transition to neighboring shots. Faces, hair, accessories, costume, object positions, architecture, lighting, motion and story each get a verdict. Similar color or a high embedding score is insufficient evidence of the same character.
6. **Repair narrowly.** Regenerate or edit the failed take with the specific discrepancy recorded. Keep successful takes fixed. Use a fresh canonical reference when entering a new shot instead of uncritically propagating a drifting final frame.
7. **Assemble and mix.** A longer episode selects qualified takes, then adds timed dialogue, room tone, foley, music, transitions and delivery formats. A professional timeline and sound stage remain substantial work beyond this milestone.

Persistent 3D geometry constrains geography; image references constrain appearance; voice references constrain sound; editorial review decides whether a take actually satisfies them. None is a universal guarantee. This combination is the practical direction for Shutter's ambition.

## First production and next gates

The Last Light uses two original adult characters, Mira and Sol, in a mountain observatory around an amber orb. It begins with a two-shot, Mira's close-up and Sol's reverse. The prepared requests are 121 frames at 24 fps and 768 × 512, with distinct recorded seeds. A separate Moment, A quiet signal, verifies the fast creation path without an additional model run.

The durable workbench, generated assets, Blender blockout and actual run report are retained together. Tests cover save conflicts, snapshots, source integrity, unknown submission, actual image upload, chosen takes and invalid output handling. Browser checks exercise saved changes and reload, not only static screenshots.

After this baseline: resolve H3 deployment rights, qualify its actual mixed-reference path, compare a Blender-directed take to its geometry, add voice/performance continuity, then qualify a 30–60-second scene before a five-minute episode. A twenty-minute result is a production of many reviewed shots. It is not evidence that one model remembers an entire episode. Runtime and retry costs should be measured before committing to a long unattended run.
